## 2. Детальный разбор выявленных проблем и внесенных исправлений

### 🛠️ 1. Фильтрация задач по привычкам (Today View)
* **Проблема:** При клике на карточку привычки задачи не фильтровались по выбранной привычке, отображались только задачи на текущий день, а при клике на привычки без задач отображался общий список.
* **Причина:** В `today-view.tsx` отсутствовала передача активной привычки в фильтр задач и не было семантического сопоставления между заголовком привычки (например, «Играть в игры») и задачами (например, «Поиграть в CounterStrike 2»).
* **Решение:**
  - Реализована функция умного сопоставления `taskMatchesHabit(task, habit)`:
    - Прямая привязка по `habitId` и тегам.
    - Семантический поиск по ключевым словам (игры/гейминг, музыка, тренировки/спорт, чтение).
    - Поиск по корням слов заголовка привычки.
  - При выборе привычки отображаются **все задачи по этой привычке со всех дней** (не только за сегодня).
  - При выборе привычки без задач (например, «Прослушивание музыки») отображается аккуратное пустое состояние (0 задач).
  - Добавлен баннер активного фильтра привычки с кнопкой быстрого сброса «Все задачи».
  - В `habits-widget.tsx` добавлена подсветка активной выбранной карточки (`ring-2 ring-primary`).

---

### 🛠️ 2. Дублирование общих задач при совместном создании
* **Проблема:** Когда пользователь давал общую задачу себе и другу (например, «поиграть в кс с Вовой»), в списке задач появлялись две одинаковые задачи.
* **Причина:** В `app/api/telegram/route.ts` для флага `isBothShared` создавались две отдельные записи в БД (одна для получателя, вторая для автора), а метод `getAllTasks` в `lib/backend/db.ts` находил обе записи через `OR: [{ ownerChatId }, { authorChatId }, { assignees }]`.
* **Решение:**
  - В `app/api/telegram/route.ts` создание задачи для `isBothShared` оптимизировано: теперь создается **ровно одна запись** с `ownerChatId: authorChatId` и `assignees: [authorChatId, friendChatId]`, что гарантирует получение задачи обоими пользователями без дублей.
  - В `lib/backend/db.ts:getAllTasks` добавлен фильтр дедупликации по составному ключу `(title + dueDate + dueTime + authorChatId)`, что исключает показ старых дубликатов.

---

### 🛠️ 3. Удаление раздела «Матрица Эйзенхауэра»
* **Проблема:** Пользователь запросил полностью убрать отдельный раздел матрицы Эйзенхауэра из интерфейса.
* **Решение:**
  - Раздел полностью удален из бокового меню `components/sidebar.tsx` и навигации.
  - В разделе «Сегодня» сохранена аккуратная кнопка «Авто-план дня», которая производит сортировку списка без необходимости перехода на отдельный экран.

---

### 🛠️ 4. Очистка интерфейса заметок (Notes View)
* **Проблема:** Под строкой поиска заметок находилась лишняя горизонтальная панель фильтров (тегов/папок), дублирующая левую панель папок.
* **Решение:**
  - В `components/views/notes-view.tsx` удален дублирующий блок тегов/кнопок под поиском.
  - Сохранена удобная трехуровневая структура в стиле Apple Notes:
    1. Левая колонка: древовидные папки и категории.
    2. Средняя колонка: поиск и список заметок выбранной папки.
    3. Правая колонка: редактор с поддержкой Markdown и превью.

---

### 🛠️ 5. Монохромные бейджи и эмодзи (Inbox & Task Item)
* **Проблема:** Во «Входящих» и карточках задач бейджи общих и порученных задач использовали цветные эмодзи (`🤝`) и яркий зеленый фон.
* **Решение:**
  - В `components/task-item.tsx` бейджи заменены на монохромные символы:
    - `▪ Общая задача`
    - `▫ Порученная задача`
  - Фон бейджей приведен к нейтральному стилю дизайн-системы (`bg-muted/60 text-foreground/80 border border-border/60`).
  - Во «Входящих» (`inbox-view.tsx`) заголовки секций переведены на монохромную стилизацию.

---

### 🛠️ 6. Модуль часовых поясов и распознавание естественного языка
* **Проблема:**
  1. В `parseTimezoneInput` проверка `.includes('+3')` ошибочно срабатывала на `+30`.
  2. Регулярное выражение в Telegram-боте не учитывало кириллицу (`\w` не захватывало русские буквы), из-за чего запросы вроде «мой часовой пояс Москва» или «поставь часовой пояс Екатеринбург» не распознавались.
  3. `vk/callback/route.ts` импортировал функцию напрямую из файла маршрута `app/api/telegram/route.ts`, что является антипаттерном в Next.js.
  4. При вызове `/timezone` без аргументов в VK-боте переменная ошибочно получала значение `"/timezone"`.
* **Решение:**
  - Создан единый модуль `lib/backend/timezone.ts` с поддержкой всех 11 часовых поясов РФ, точным разбором числовых смещений (`+3`, `+03`, `UTC+3`, `GMT+5`) с проверкой границ чисел, и валидацией через `Intl.DateTimeFormat`.
  - В Telegram-боте регулярное выражение обновлено на `/(?:мой\s+|установи\s+|поставь\s+|смени\s+|измени\s+)?часовой\s+пояс\s*(?:на|:)?\s*([+\w\s/–\-а-яёА-ЯЁ]+)/iu`.
  - В VK-боте и Telegram-боте импорт переведен на `@/lib/backend/timezone`.
  - В VK-боте исправлен разбор аргументов команды `/timezone`.
  - В `app/api/user/timezone/route.ts` добавлена валидация корректности таймзоны перед сохранением в БД.

---

### 🛠️ 7. Безопасность и логика промокодов
* **Проблема:**
  1. Эндпоинт `/api/admin/promocode` не содержал проверки прав администратора.
  2. В `/api/promocode` активация промокода тарифа Premium перезаписывала существующий тариф Безлимит (`unlimited`), понижая уровень подписки пользователя.
* **Решение:**
  - В `/api/admin/promocode` добавлена строгая проверка `const { isAdmin } = await isCallerAdmin(req)` и санитизация числовых параметров.
  - В `/api/promocode` добавлена защита от понижения тарифа: для пользователей с планом `unlimited` сохраняется Безлимит с продлением срока действия.
